Direct dependencies are permissively licensed and are documented in
[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Sparkle contains additional
notices carried in `Barline/Resources/Acknowledgements.rtf`. Dependency changes
must update the lockfile, notice inventory, acknowledgements, and local full CI.

The license files at these exact revisions were inspected. Sparkle's license
also includes the notices for bsdiff, sais-lite, orlp/ed25519, and
SUSignatureVerifier. At the 2026-08-28 audit, the RTF and generated PDF named
the same five direct dependencies and neither contained the removed Semaphore
package. Both still identify LaunchAtLogin using its older project name and URL;
this is attribution-compatible but should be corrected to LaunchAtLogin-Modern
when acknowledgements are next regenerated.

On 2026-09-11 the Sparkle 2.9.6 license at the pinned revision was re-inspected.
It carries the same bsdiff, sais-lite, orlp/ed25519, and SUSignatureVerifier
notices, and the bundled acknowledgements already name each of them. Release
packaging removes Sparkle's x86_64 slices so every distributed binary is
arm64-only.

On 2026-09-12 CompactSlider moved to 2.1.0 and the license at the pinned
revision is Copyright (c) 2025 Alexey Bukhtin, so
`Barline/Resources/Acknowledgements.rtf` was corrected from the 2022 line it
carried, and `Barline/Resources/Acknowledgements.pdf` was regenerated from it.
The PDF is the artifact `AboutSettingsPane` shows the user; the RTF is excluded
from the app bundle and is the source of truth. Regenerate with:

```
swift script/generate_acknowledgements.swift \
    Barline/Resources/Acknowledgements.rtf \
    Barline/Resources/Acknowledgements.pdf
```

The generator lays the RTF out at a 504 pt content width and emits it as a
single page through `NSPrintOperation.pdfOperation`, so it never paginates.
Always regenerate through this script rather than re-rendering by hand: a
paginating render duplicates a license paragraph across the page break.

Its output is stable in content but not byte-identical across runs. Quartz
stamps `CreationDate` and `ModDate` into the PDF, so two runs over an unchanged
RTF differ in 68 bytes covering only those timestamps, with identical extracted
text, font table, geometry, and total size. Regenerating therefore always
produces a diff; compare `pdftotext -layout` output, not checksums, when
deciding whether a regeneration actually changed anything.

## Asset provenance

The application icon, `Resources/BarlineIcon.png`, and Barline control-item
icons are original Barline geometry generated by `script/generate_icon.swift`.
`Resources/BarlineIcon.svg` is the editable vector rendition. The generator and
SVG encode the geometry independently, so both must be updated and visually
compared after a design change.

The following files are byte-identical to the imported Ice baseline
`79654cd8c249e2a1465a262cfda7175346fe7772`:

- Dot control-item fill and stroke PNGs
- Ellipsis control-item fill and stroke PNGs
- `Barline/Resources/Assets.xcassets/Warning.imageset/Warning.png`
- `Resources/rearranging.gif`
- `Resources/rearranging.mov`

No separate per-asset author, source file, or license notice was present in the
vendor baseline. They are retained as Ice project material under the
repository's GPLv3-or-later license and `NOTICE.md` attribution. The dot,
ellipsis, and warning images are app resources. The rearranging media are
repository documentation assets and are not Xcode app resources. Before a
public release, retain this explicit GPL provenance, obtain more specific
upstream provenance, or replace them with documented original Barline assets.

## Development tools

`Brewfile` declares Actionlint, ShellCheck, SwiftFormat, and SwiftLint. Bootstrap
verifies or installs them locally. GitHub repository hygiene may use only
documented, pinned tools/actions and does not compile the macOS app.

The tools are development-only and are not linked into Barline. Actionlint,
SwiftFormat, and SwiftLint are MIT-licensed; ShellCheck is GPLv3. The GitHub
workflow pins actionlint 1.7.12 by archive checksum and `actions/checkout` by
commit SHA. The local Brewfile has no formula versions or committed lockfile,
so `brew bundle` is not an exact tool-version reproduction mechanism; CI
evidence must record the installed versions.

No dependency is authorized to add analytics, remote AI, advertising, an
account system, or a second update channel. Do not commit downloaded binary
tools without a pinned version, verified checksum, license review, and explicit
documentation.
